# DAYBOARD — Windows x64 / Tauri 2

Персональная Kanban-доска с компактным виджетом, задачами на день и неделю, чек-листами и системным треем. **Это исходный проект нативного Tauri-приложения, а не установщик**. Файлы `web/` — ресурсы интерфейса, которые Tauri включает внутрь собранного `.exe`; браузер не требуется запускать отдельно.

## Как получить настоящий установщик без установки компиляторов (GitHub Actions)

1. Создайте пустой репозиторий на GitHub (лучше приватный).
2. Загрузите в **корень репозитория** все файлы этого проекта, включая скрытую папку `.github/workflows/`.
3. Откройте **Actions → Compile and smoke-test DAYBOARD on Windows x64 → Run workflow** (разрешите Actions в настройках репозитория, если требуется).
4. Дождитесь статуса `Success`. В конце запуска откройте **Artifacts → DAYBOARD-Tauri-Windows-x64**.
5. Внутри будут установщик `...setup.exe` и отдельно `dayboard.exe`. Для повседневного использования предпочтительнее **установщик NSIS**: он устанавливает продукт и обеспечивает корректный контекст Windows-уведомлений.

В CI проверяются компиляция и unit-тесты Rust, синтаксис JavaScript, структура PE x64 и запуск реального `dayboard.exe` с инициализацией SQLite. Важно: runner `windows-2025` основан на **Windows Server 2025**, а не на Windows 11. Перед производственным использованием требуется дополнительная проверка установщика на физическом ПК под Windows 11 (трей, монитор, уведомления, автозапуск, потребление памяти).

## Локальная сборка на Windows 11

Требуется:
- Rust MSVC (`rustup.rs`), актуальный стабильный компилятор.
- Microsoft Visual Studio Build Tools + **Desktop development with C++** + Windows SDK.
- Microsoft Edge WebView2 Runtime (на Windows 11 обычно установлен).
- Интернет для первой загрузки зависимостей Rust.

Откройте PowerShell в папке проекта, выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\BUILD_WINDOWS.ps1
```

После успешного smoke test установщик лежит в `src-tauri\target\release\bundle\nsis\`. На PC с Windows 11 установите его и протестируйте уведомления (работают только в установленном приложении), поведение окна, трей и перенос на второй монитор.

## Структура

- `web/` — UI, CSS, встроенный фронтенд (не веб-сервис).
- `src-tauri/src/lib.rs` — Rust/Tauri API, SQLite, автозапуск, трей, напоминания и резервное копирование.
- `src-tauri/tauri.conf.json` — нативная конфигурация, Windows NSIS.
- `tests/test_ui_native_bridge.py` — проверка интерфейса с эмуляцией IPC (не тест Windows executable).
- `tests/smoke-windows.ps1` — Windows runtime smoke test после сборки.
- `.github/workflows/build-windows.yml` — Windows pipeline, прикладывающий оба EXE-файла как GitHub artifact.

## Известные ограничения

- Данные Tauri сохраняются локально в SQLite (таблица `app_snapshot`, JSON-снимок приложения). Полностью нормализованная модель для синхронизации с телефоном ещё не реализована.
- Системные напоминания работают, пока приложение запущено (включая трей), и требуют установленной Windows-сборки. Нажатие на уведомление пока не открывает конкретную карточку.
- Глобальная комбинация клавиш вне окна не реализована.
- Windows 11 нагрузочное тестирование памяти и CPU, multi-monitor UX и тест в автозапуске требуют установленного `.exe`.
- Для распространения незнакомым пользователям рекомендуется подписать бинарник; неподписанные `.exe` могут вызывать предупреждение SmartScreen.

## Конфиденциальность

Нет удалённой авторизации, внешней аналитики и сетевого API. Данные остаются на компьютере. Для резервной копии выберите «Экспорт» в настройках.
